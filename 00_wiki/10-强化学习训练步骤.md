## 一、训练步骤总览（官方 AGENTS.md 7 步法）

```
① 选模板 env → ② 仿真里先验证物理假设 → ③ 写 cfg（惯例看下方）
→ ④ 写 cfg 测试（CPU 跑）→ ⑤ 冒烟测试（64 envs × 5 iters）
→ ⑥ 正式训练（看 wandb 曲线）→ ⑦ 导出 ONNX → ⑧ 部署彩排 infer_policy.py
```

### 步骤① 选最接近的模板（不要从零写）

| 任务类型 | 模板 env |
|---|---|
| 走路/速度跟踪 | `Mjlab-Velocity-Flat-MicroDuck`（主菜谱 + 共享基座） |
| 摔倒后起身（episodic → pose） | `Mjlab-StandUp-*` |
| 坐↔站切换（two-state） | `Mjlab-SitStand-*` |
| 动态翻滚（roulade） | `Mjlab-Roulade-Flat`（cfg docstring 里有 5 次失败教训） |
| 踢球 | `Mjlab-BallKick-Flat` |
| 轮滑系（rollers） | `Mjlab-Velocity-Flat-MicroDuck-Rollers` |

用 `uv run list-envs` 看注册表。每个任务还有 **Backlash 孪生变体**（`-Backlash-` 插入任务名），
带 ±1° 齿轮回差建模——**上真机前用这个训**。

### 步骤② 训练前先验证物理（官方最强调的一条）

- 目标姿态必须是稳定平衡：给噪声初始态、按住 ctrl 3 秒，**检查是否 TILT** 而不是只看高度
- 目标高度从**当前模型实测**取（站姿下 trunk z），不要跨模型版本沿用——
  官方 STAND_Z 错 5mm 让一个目标三天训不出来

### 步骤③ cfg 惯例（贴着官方写，别自创）

- `ENABLE_*` 开关 + 调好的常数放在 cfg 文件头
- 工厂函数 `make_..._env_cfg(play: bool, rough: bool)`
- 在 `tasks/__init__.py` 注册（有回差需求就加 `_BACKLASH_TASKS`）
- 每个 env 独立 `experiment_name`
- **不变量（动了就 sim2real 崩）**：
  - obs 恒 61 维 = 48 本体感知 + `[twist(3), head_pose(4), body_pose(6)]`，不用的槽**零填充保留**
  - 14 舵机关节序：0-4 左腿 / 5-8 颈头 / 9-13 右腿；**不要硬编码关节 index**，用 mdp.py 的 helper
  - 被动关节一律 `passive_` 前缀；选择器用 `^(?!passive_).*`
  - 执行器是 BAM（电压级 XL330 模型）——独立 env 必须注册 `expand_bam_friction_fields` 事件
  - 归一化器必须烤进 ONNX（`scripts/export.py` 自动做；**禁止手工转 checkpoint**）
  - 训练时策略**不带动作低通**——部署端有 0.5/0.7 低通，两端必须一致
  - 域随机化不得跨 reset 累积（官方踩过的坑，蛰伏数月才暴露）

### 步骤④ cfg 测试（CPU 免费）

仿 `tests/test_*_cfg.py`：关节 index 在真实模型上能解析、奖励项符号正确、gate 开关符合预期。

### 步骤⑤ 冒烟测试（**每次必跑，几分钱防 95% 配置错误**）

```bash
uv run train <TASK_ID> --env.scene.num-envs 64 --agent.max_iterations 5
```

过了 = 无 NaN、obs 61 维、每个奖励项都算得出、ONNX 能导出。

### 步骤⑥ 正式训练（本机 M5 Pro 实测速度）

```bash
# 本机（E3 已验证通路）：
uv run train-walk --envs 16 --steps 500000 --run-name first-gait   # ~40 秒
# 正式步态：
uv run train-walk --envs 32 --steps 3_000_000 --run-name gait-v1   # ~3-5 分钟
```

官方参考（mjlab 4096 envs，需 CUDA）：
- 简单 episodic 技巧：~1000 iters（= 2400 万 env-steps）
- 步态/重课程恢复：4000-6000 iters

**看曲线**（wandb 项目 `mjlab_microduck`，或本机 tensorboard `runs/<name>/tb`）：
- 总奖励上升 + episode 长度符合任务语义
- **每个惩罚项 `Episode_Reward/<penalty> ≤ 0`**（符号写反 = 双重负号 = 政策在奖励违规行为）
- **主任务项真的在长**（总奖励可能只靠正则涨，把戏从不发生）
- 曲线在课程阶段边界**骤降 = 阶段节奏错了**，拉长阶段、别提前

**预期 2-5 轮 reward-hacking 打地鼠**——官方说这很正常，他们的教训清单如下：

| 官方教训 | 一句话 |
|---|---|
| 奖励符号反转 | 负权重套自消惩罚 = 双重负 = 奖励违规。检查：惩罚项必须 ≤0 |
| RL 抠字眼 | 动作定义写进**硬状态 gate**（接触/朝向/latch），不要用小惩罚暗示 |
| Jackpot | "到达 X 后每步给钱" → 政策暴力冲线。用 slewed 内部目标（领先=零收益） |
| 坏状态给正奖励 | 政策会赖在最便宜的合格姿势里薅。改用 potential shaping（Δprogress） |
| 早期收税 | 技能还在探索时就上平滑惩罚 → "不动"胜出。**课程从 ~0 引入** |
| 跨 env 抄权重 | PPO 看的是**相对优势**——正任务栈变 4 倍，同一惩罚弱化 4 倍，按"奖励质量"比 |
| 高斯 std 太紧 | std ≈ 你还在乎的误差，不是最大误差。先问误差可逃逸还是行为固有 |
| 乘法组合 > 加法求和 | 目标态附近加法有折中盆地，乘法把短板一票否决（std 放宽到当前策略能看见分） |

### 步骤⑦ 导出 ONNX（必须走官方脚本）

```bash
uv run scripts/export.py <TASK_ID> --wandb-run-path <...>

```

### 步骤⑧ 部署彩排（上真机前必做）

```bash
# 官方 CPU MuJoCo 彩排（E1 环境已验证可跑）
```

## 二、Sim2real 脚注（官方"花了真金白银的几周"踩的坑）

- aarch64（GB10/Spark）PyPI torch 是 CPU 版 → 必须 `[tool.uv.sources]` 把 torch 指向 cu129 索引
  且 `torch==2.9.1` 精确 pin（有测试锁着，别删）
- IMU 域随机化只能练出对"失调量级"的容忍，**装机偏差是运行时标定的事**
- 25cm 机器人自然翻滚角速度 3.5-5.5 rad/s——别用人类直觉的转速上限去封，压冲击和抖动即可
- 上真机前用 `infer_policy.py` 多策略热切换彩排，确认命令槽写法
