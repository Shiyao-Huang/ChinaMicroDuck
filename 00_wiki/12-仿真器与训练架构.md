# 12 · 仿真器与训练架构（这个方案里用什么来训）

> 一句话：**物理仿真器 = MuJoCo（CPU 版，MJCF 场景描述），学习算法 = PPO（Stable-Baselines3 / rsl_rl）**。
> 两者关系：MuJoCo 负责"鸭子动了之后世界变成什么样"，PPO 负责"下一步该给 14 个舵机什么指令"。

## 一、训练循环里发生了什么（每 20ms 一步，共百万步）

```
┌─────────────────────────── 每个控制步 (50Hz, 20ms) ───────────────────────────┐
│                                                                              │
│  观测 obs[61] ──▶ 策略网络(神经网络) ──▶ 动作 act[14]                          │
│  (61维: 姿态/角速度/关节角/命令)      (14个舵机目标位置)                        │
│        ▲                                   │                                 │
│        │                                   ▼                                 │
│  MuJoCo 物理仿真步 (dt=0.005s × 4 子步)      奖励函数打分                        │
│  刚体动力学: 重力/摩擦/碰撞/电机扭矩         (卡点+摆头+站直+不摔…)               │
│        │                                   │                                 │
│        └─────────── 下一个状态 ◀── 累积经验 ──┘                                 │
└──────────────────────────────────────────────────────────────────────────────┘
      PPO 用几十万条 (状态,动作,奖励) 经验更新策略网络权重 → 下一轮更好
```

## 二、三层分工

| 层 | 是什么 | 在哪跑 | 我们实测 |
|---|---|---|---|
| **物理仿真器** | MuJoCo（MJCF 格式描述鸭子的质量/关节/碰撞体） | CPU（M5 Pro 7900 步/s；4090 也能跑但无加速意义） | E1/E3 已验证 |
| **强化学习算法** | PPO（近端策略优化，Stable-Baselines3 实现） | CPU/MPS | v5→v6b 全程用它 |
| **GPU 加速版**（可选） | mjlab = MuJoCo Warp（把物理仿真整个搬进 CUDA） | 仅 NVIDIA GPU | 官方 4096 envs 用这个 |

## 三、官方与本仓库的关系

- **官方 microduck_rl**：mjlab（MuJoCo Warp on CUDA）+ rsl_rl，4096 并行环境，需要 NVIDIA GPU
- **本仓库 microduck-lab**：CPU MuJoCo + SB3 PPO，32 envs，**同一 MJCF 模型、同一 61/14 部署契约**
- **同一个 MJCF**：鸭子模型（质量 0.737kg、14 关节、接触面）来自官方 Onshape 导出，物理参数相同
- 4090 的用法：把官方 mjlab 栈跑起来 → 4096 envs 并行 → 训练速度提升 ~100 倍（本机 12 分钟 = 官方 7 分钟，但官方能训 4000 iters 的重课程）

## 四、为什么不用游戏引擎（Unity/Unreal/Isaac）？

| | MuJoCo | Isaac Sim/Gym |
|---|---|---|
| 接触求解精度 | 高（软接触，适足机器人标准） | GPU 并行强但接触噪声大 |
| MJCF 支持 | 原生 | 需转 USD |
| 学术界足式机器人 | 标准选择 | 走量场景 |
| 官方 microduck_rl | ✓ mjlab | ✗ |

## 五、sim2real 关键设计（为什么仿真里的技能能搬到真鸭）

1. **BAM 执行器模型**：不是理想电机——模拟 XL330 的电压-扭矩曲线、齿轮回差(±1°)、摩擦
2. **域随机化**：每次 reset 随机电池电压 6.5-8.2V / 摩擦系数 / 指令延迟 3-6 步 / IMU 失准
3. **同一观测契约**：obs[1,61]→act[1,14]，仿真和真机逐字节一致（E1 已验证互跑）
4. **50Hz 控制环**：与真机 robotd 完全同频
