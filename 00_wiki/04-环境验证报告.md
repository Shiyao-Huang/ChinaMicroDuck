## E1 本地仿真环境 ✅（官方策略 + MuJoCo 本机实跑）

环境：`05_sim/.venv`（Python 3.12.13 + mujoco 3.12.0 + onnxruntime 1.29.0 + numpy 2.5.2 + better-actuator-models 1.0.2）

```bash
# 环境搭建
uv venv --python 3.12 05_sim/.venv
uv pip install --python 05_sim/.venv/bin/python mujoco onnxruntime numpy better-actuator-models

# 实跑官方行走策略（macOS 必须 mjpython）
cd 01_official/microduck_rl
05_sim/.venv/bin/mjpython scripts/infer_policy.py \
  --walking ../../01_official/microduck-policies/alpha_walking.onnx \
  --new-cmd-obs --debug
```

实测输出（摘录）：

```
Loading walking policy: alpha_walking.onnx
Walking policy input: obs, shape: [1, 61]        ← 61 维观测契约
Walking policy output: actions, shape: [1, 14]   ← 14 维动作
Control frequency: 50 Hz (decimation: 4)
Current limit: 1.75 A -> torque limit +/-0.6405 Nm (kt=0.3660)
Step 900..1450: trunk_z=116.4 mm, quaternion≈[1,0,0,0], fwd=+0.00/+0.00 m/s
```

结论：官方 alpha_walking 策略在本机 MuJoCo 50Hz 稳定站立运行，观测/动作/力矩限制全部符合文档。
踩坑记录：
1. 缺 `bam` 模块（MJCF 用 BAM 自定义执行器标签）→ 装 `better-actuator-models`
2. macOS 上 `mujoco.viewer` 必须用 `mjpython` 启动
3. **`--new-cmd-obs` 必须加**：Hub 上的 9 个策略是 61 维新契约，脚本默认 51 维旧版会报
   `Got 51 Expected 61`

## E5 STL 网格可打印性 ✅

脚本：`05_sim/stl_check.py`（trimesh 5.1.0），对象：`02_cad/upstream_stl/` 47 个 STL。

| 检查 | 原始(process=False) | 顶点熔合后(process=True) |

| 水密 watertight | 0/47 | **47/47** |
| 绕向一致 | 47/47 | 47/47 |

结论：
1. 上游网格是仿真件（重复顶点未熔合），切片软件/修复后可打印 —— 与社区判断一致
